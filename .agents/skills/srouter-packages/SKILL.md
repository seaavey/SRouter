# SRouter Packages Skill

Use this skill for `packages/*`: Zod contracts, database access, executors, translators, constants, providers, and pricing. Shared packages own reusable behavior and must remain independent of apps.

## When to Use

- `@srouter/types` schemas and `snake_case` contracts.
- `@srouter/db` queries/schema, `@srouter/executors` upstream drivers/SSE, `@srouter/translator` pure mappings.
- `@srouter/constants` versions/provider catalogs, `@srouter/providers` registry/OAuth/quota, or `@srouter/pricing` cost calculations.

## Repository Rules

- Read `RULES.md`, `CODING-STYLE.md`, and `DESIGN.md` in `/home/seaavey/Obsidian/SRouter/` before editing.
- Dependency direction is one-way: apps import packages; packages never import apps.
- Contracts live in `@srouter/types`; derive TypeScript types with Zod and do not duplicate them in apps.
- Database queries use parameterized `?` placeholders only. Document non-automatic schema changes in `DB-MIGRATION.md`.
- Translators are pure functions: no fetch, filesystem I/O, clocks, timers, or environment reads.
- Provider metadata and versions belong in `@srouter/constants`; generated data files must be regenerated by their package script.
- Keep strict typing, ESM imports, PascalCase helpers/guards, and zero `any`.

## Procedure

1. Inspect package exports, dependency boundaries, tests, and all consumers before editing.
2. Read the matching reference under `references/`.
3. Update the canonical schema/contract first when an API shape changes, then migrate consumers.
4. Keep the change minimal and preserve runtime behavior outside the requested contract.
5. Add focused tests for changed behavior and update `/home/seaavey/Obsidian/SRouter/PROGRESS.md`.

## Verification

Run only touched package checks from that package directory:

```text
cd packages/<package> && pnpm run build
cd packages/<package> && pnpm exec tsx --test tests/<file>.test.ts
pnpm exec prettier --check <changed-files>
git diff --check
```

Never run root monorepo build/test/lint locally. For generated data, run the package update script, compare added/removed/changed entries programmatically, then build and test the package.
